1. What is byte pair encoding (BPE), and why is it useful for language models?

Correct: A. BPE builds a vocabulary by repeatedly combining frequent neighboring symbols into larger units. The resulting tokenizer can use whole words or smaller pieces depending on what it learned. This provides a practical way to represent common text efficiently while still splitting unfamiliar words into known components.

Character, subword and whole-word alternatives

2. Why is BPE a useful compromise between character-only and whole-word tokenization?

Correct: C. Character-level tokenization can create long sequences. Whole-word tokenization needs many vocabulary entries and has problems with unseen words. BPE balances the two by learning useful multi-character pieces while retaining smaller units. Exact token counts vary with the training data, merge rules, and the text being encoded.

3. How does the BPE training algorithm decide which symbols to merge next?

Correct: B. BPE starts with small pieces such as characters or bytes. It counts adjacent pairs in the training text and chooses a frequently occurring pair to combine. This creates a new vocabulary entry. The process repeats on the updated pieces, with specific implementations controlling tie-breaking, boundaries, and stopping conditions.

4. How do a BPE vocabulary and its ordered merge rules work together during tokenization?

Correct: D. A BPE vocabulary contains tokens the encoder can output, usually with assigned numeric IDs. Merge rules describe allowed combinations of adjacent pieces and the order in which they apply. The tokenizer uses both to segment new text. Mixing rules and vocabulary from different versions can produce incompatible results.
Q5PRACTICAL APPLICATION
05 / TECHNICAL ILLUSTRATION

Unfamiliar words reuse familiar endings

Visual example · jump · ing · jumping

5. How can BPE process an unfamiliar word that contains a common ending such as 'ing'?

Correct: A. BPE does not require every complete word to exist in the vocabulary. It can combine familiar subword pieces with smaller units for a rare prefix or root. A learned ending such as ing may appear as one token if the merge rules and token boundaries allow it. Real splits vary.
Q6ADVANCED UNDERSTANDING
06 / TECHNICAL ILLUSTRATION

Byte-level BPE can represent new characters

Visual example · é · C3 A9 · 2 bytes

6. What advantage does byte-level BPE have over a toy tokenizer based on known characters?

Correct: B. Byte-level BPE begins with byte values, so the input can be encoded even when a particular Unicode character was not seen during training. Learned merges then make some byte sequences more compact. This avoids unknown-character failures found in simple character-based examples, though unusual characters may require multiple tokens.
Q7SMART-LEVEL REASONING
07 / TECHNICAL ILLUSTRATION

A rare brand name creates many pieces

7. A rare brand name uses many tokens. How would you investigate this behavior?

Correct: C. Encode the exact input and inspect the returned token pieces and IDs. Spaces, punctuation, uncommon spellings, and multi-byte text can change segmentation. Compare results against the configured tokenizer and its vocabulary. More tokens can affect context usage and compute, but do not automatically indicate a broken implementation.
Q8INTERVIEW QUESTION
08 / TECHNICAL ILLUSTRATION

8. In an interview, how would you select a BPE tokenizer for a multilingual language model?

Correct: D. Begin with a diverse sample of the languages, scripts, and formats users will send. Compare token counts, reversibility, rare-character behavior, and vocabulary size. Assess the sequence-length versus vocabulary-memory trade-off. Keep the trained model paired with its exact tokenizer, and test realistic multilingual edge cases before deployment.
