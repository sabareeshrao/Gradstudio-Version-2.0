Context

Large language models (LLMs) are neural-network systems trained on extensive language data to interpret and produce text. The word “large” describes model scale rather than an officially fixed parameter threshold.

This lesson focuses on what choosing and serving an LLM actually requires: model capacity, working memory, meaningful evaluation, quantization, bias, domain-specific tests, and responsible deployment decisions.

1. What does the word “large” describe in large language models, and is there a universal parameter count that defines an LLM?

Correct: B. Large language models learn many numerical parameters from extensive language data. “Large” describes scale rather than a universally fixed parameter threshold. A model's size, training data, architecture and capabilities all matter. Two models with similar parameter counts can behave differently, so parameter count alone is not a complete quality label.

2. Why can doubling an LLM's parameter count fail to deliver a matching improvement in useful performance?

Correct: D. More parameters can provide greater capacity, but improvements also depend on suitable training data, optimization, architecture, and computing resources. Extra capacity may be underused when training is poor or data is limited. Measure useful task results rather than assuming twice the weights gives twice the accuracy. Scaling has resource and quality trade-offs.

3. Why can serving an LLM to many users require more memory even though the model weights do not change?

Correct: A. An inference server holds model weights in memory. During generation, it also stores temporary working state, often including a key–value attention cache. Longer token sequences and more active requests can increase that state. The weights remain unchanged, but total memory demand rises, so concurrency and prompt length matter when planning capacity.

4. What can perplexity tell you about a causal language model, and why should it not replace task-level evaluation?

Correct: C. Perplexity summarizes how well a causal language model predicts tokens in a selected evaluation set. Lower can indicate better predictive fit under comparable tokenization and test conditions. It does not by itself measure factual accuracy, instruction following, fairness, or business usefulness. Evaluate those behaviors separately with representative tasks and human review.

5. A developer wants an LLM to fit in limited GPU memory. What is the main trade-off of reducing weight precision?

Correct: D. Quantization stores model weights with fewer bits, such as reducing a 16-bit representation to 8-bit or 4-bit values. This can greatly reduce weight memory, though practical savings vary with scale and overhead. Reduced precision can change output quality and speed, so test the quantized model on your tasks and actual hardware.

6. How could biased patterns in training data affect an LLM's answers, even when its output sounds fluent?

Correct: B. Language models can absorb stereotypes or uneven coverage from training material. Their confident writing style does not reveal whether answers are fair. Teams should test relevant prompts across groups and contexts, examine the data and system design, and apply suitable mitigation. Avoid claiming complete fairness from one benchmark or a handful of examples.

7. An LLM scores well on general tests but struggles with specialist maintenance reports. What should developers investigate?

Correct: C. Strong general benchmark scores do not guarantee success on unfamiliar specialist language. Maintenance reports may contain rare terms, formats, and assumptions absent from evaluation examples. Create representative domain tests, label common failures, and compare prompting, retrieval or adaptation methods. Choose changes based on measured improvement rather than benchmark reputation alone.

8. You must deploy an LLM for confidential internal documents. How would you choose between a local model and a hosted service?

Correct: A. A local model offers direct control over infrastructure but requires hardware, maintenance and security operations. A hosted service may simplify scaling, yet data-handling terms and network dependencies require review. Evaluate both against real tasks, confidentiality rules, response time, total cost, reliability and access controls before deciding where to run it.
