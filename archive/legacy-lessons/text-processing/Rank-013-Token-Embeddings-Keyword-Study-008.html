1. What is a token embedding, and how does it differ from a token ID?

Correct: A. A token ID is an integer label for a vocabulary entry. A token embedding is a vector of learned numerical features stored in a corresponding table row. The ID allows the model to retrieve the vector. Unlike the ID number itself, an embedding participates meaningfully in neural-network calculations and training.

2. Why does a Transformer use learned embedding vectors rather than treating token IDs as ordinary numbers?

Correct: C. Token IDs are arbitrary labels. Feeding them as magnitudes would incorrectly suggest that nearby integers represent similar tokens. An embedding matrix instead provides a trainable vector for each ID. These vectors form the starting features for attention and feedforward layers, which build more useful representations using the surrounding text.

3. How does an embedding layer process a sequence of token IDs?

Correct: B. An embedding matrix contains one row for each vocabulary ID. Given a sequence of IDs, the layer retrieves the corresponding vectors in the same sequence order. If the input has three tokens and each embedding has four features, the unbatched output has a three-by-four shape. These values are numeric features, not text.

4. What do vocabulary size and embedding dimension describe in an embedding matrix?

Correct: D. The embedding matrix typically has shape vocabulary_size by embedding_dimension. The number of rows determines which token IDs can be looked up, while the width specifies how many numeric features each vector has. A wider table or larger vocabulary uses more parameters and memory. Both dimensions must agree with the model architecture.

5. When can the learned values of token embeddings change?

Correct: A. Token embedding values are usually trainable parameters. During training, loss gradients can update rows involved in the forward computation. At ordinary inference time, the learned table generally remains fixed while the model answers prompts. Fine-tuning can change embeddings when that parameter group is trainable, depending on the chosen setup.

6. How do token embeddings differ from representations created later by Transformer blocks?

Correct: B. The lookup vector provides a learned starting representation associated with the token ID. Transformer layers then combine information across the input sequence, allowing the same token to develop different hidden states in different contexts. This explains why an input token embedding and a final contextual representation should not be treated as interchangeable.

7. Your embedding lookup fails for one input batch. What should you inspect first?

Correct: C. Check the token ID tensor's data type, shape, minimum, and maximum values. An out-of-range ID can fail because its embedding row does not exist. Also compare the tokenizer vocabulary with the matrix size and verify expected embedding width. These checks are more informative than guessing about token meaning.

8. In an interview, how would you estimate the storage cost of a token embedding matrix?

Correct: D. If an embedding table has V rows and D features, it contains about V times D parameters. Multiply by bytes per value to estimate parameter storage. Training may also require gradients and optimizer state, increasing memory use. Confirm actual tensor shapes and types with profiling instead of relying only on theory.
