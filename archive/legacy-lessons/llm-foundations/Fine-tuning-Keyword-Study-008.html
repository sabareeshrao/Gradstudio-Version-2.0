Context

Fine-tuning continues training from a pretrained model's weights to improve behavior on a narrower task or data distribution. Teams choose what to update, prepare representative examples, and verify improvements without losing useful general capabilities.

The following mini-scenes are explanatory examples, not measured model outputs. Progress from the definition to a practical interview scenario.

What is fine-tuning in the lifecycle of a pretrained language model?

Correct: D. Fine-tuning begins with a model that already has learned weights and updates some or all of them using more focused data. This can improve formatting, classification, or instruction following. It differs from ordinary prompting, which changes the input context but does not update the model's parameters during inference.

Why might a product team fine-tune instead of using only the base model?

Correct: B. A base model may understand a domain yet follow the application's required behavior inconsistently. Fine-tuning can teach recurring formats, style, or decisions through repeated examples. The team should first measure the problem and compare against prompting or retrieval. Fine-tuning is useful when a demonstrated behavior gap justifies the training cost.

What happens during a typical supervised fine-tuning step?

Correct: C. Supervised fine-tuning presents examples with desired targets, computes a training loss, and uses backpropagation to update selected parameters. Some methods update most model weights; parameter-efficient methods update smaller added components. Over many batches, the system becomes better aligned with the examples, although validation is needed to detect overfitting.

Which components must be decided when planning a fine-tuning run?

Correct: A. A fine-tuning plan needs curated examples, an objective that matches the task, and a decision about which parameters are trainable. Learning rate, batching, and validation also matter. Updating every weight is different from using adapters such as LoRA. Without a held-out evaluation, improved training loss may disguise weaker real-world behavior.

A team wants a model to classify incoming bug reports into fixed categories. Which training setup fits that goal?

Correct: A. Classification fine-tuning needs examples that represent realistic inputs and trustworthy target labels. The team should decide whether to use a classification head or structured text outputs, then measure performance on held-out reports. Class balance, ambiguous cases, and formatting checks matter. A small impressive demonstration is not sufficient evidence for deployment.

What is a real risk of fine-tuning on a small, narrow dataset?

Correct: D. Training repeatedly on narrow examples can produce strong results on those examples but weaker performance elsewhere. Some fine-tuning setups also cause catastrophic forgetting, where useful earlier behavior deteriorates. Mitigations include representative data, conservative learning rates, checkpoints, and evaluations covering both the target task and retained general capabilities.

A fine-tuned assistant gives the wrong response format for new prompts, even though training loss is low. What should be investigated?

Correct: B. Low training loss does not prove that an application uses the same prompt structure as training. Differences in instruction delimiters, target masks, or examples may create poor behavior on new inputs. Compare real requests with training records, audit label quality, and evaluate representative prompts before changing architecture or adding compute.

An interview panel asks whether to fine-tune an assistant that must answer frequently changing policy questions. Which response shows sound judgment?

Correct: C. When facts change often, retrieval from maintained policy sources is usually better for freshness than treating weight updates as a knowledge database. Fine-tuning may still help the model follow a format or use evidence reliably. The team should compare both approaches, test citations and failure cases, and control what reaches users.
