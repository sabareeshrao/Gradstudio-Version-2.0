Context

Token IDs are integers from a tokenizer's vocabulary. They label text tokens so a language model can look up their learned embedding vectors. The numbers themselves are not measurements of meaning.

1. What is a token ID, and what purpose does it serve in a language model?

Correct: B. After splitting input text, a tokenizer assigns each recognized token an integer ID from its vocabulary. A model uses the ID to retrieve a learned embedding row. The number itself is simply a label, not a measure of meaning or importance. Exact ID assignments depend on the tokenizer version.

2. Why must the tokenizer vocabulary match the language model's learned embedding table?

Correct: C. An embedding table learns representations for particular token IDs. If another tokenizer gives the same number to a different token, the model retrieves the wrong learned row. Tokenizer vocabulary, special-token configuration, and model weights therefore belong together. Changing one without adjusting the others may badly damage model behavior.

3. How does tokenization turn the text 'Hello world' into a model-ready ID sequence?

Correct: A. First, the tokenizer divides the string into tokens according to its own rules. Next, it looks up each token in its vocabulary to obtain an integer. The resulting sequence may have more or fewer pieces than visible words. The integer IDs feed the embedding layer before the Transformer processes them.

4. How are special token IDs different from ordinary text token IDs?

Correct: D. Ordinary token IDs correspond to text pieces such as words, spaces, or punctuation. Special-token IDs represent reserved signals, such as an end-of-text marker, depending on the model design. Both are integers in the tokenizer's defined vocabulary. Their specific numeric values and behavior are not universal across all tokenizers.

5. What should you validate before passing token IDs into an embedding layer?

Correct: A. An embedding lookup indexes rows using integer token IDs. Values outside the available vocabulary rows can cause indexing errors, while a wrong data type or shape can fail at runtime. Validate that the IDs come from the intended tokenizer and fit the model's expected input tensor before running inference.

6. Why is token ID 500 not necessarily more similar to token ID 501 than to token ID 900?

Correct: B. IDs behave like row numbers in a lookup table. Numbers that are close together may label unrelated tokens. Meaningful similarity must be measured from learned vector representations or task behavior, not by subtracting ID values. This distinction matters when debugging tokenization and designing search or clustering experiments.

7. Two tokenizers produce different ID sequences for identical text. What should you conclude?

Correct: C. Different tokenizers can split the same string into different pieces and assign different numeric labels. Neither is automatically faulty. Inspect both the token text and decoded output, including spaces and special markers. Use the tokenizer paired with your model rather than comparing raw ID numbers across unrelated vocabularies.

8. In an interview, how would you prevent tokenizer mismatches during model deployment?

Correct: D. Package the exact tokenizer configuration, vocabulary, and special-token IDs with the corresponding model weights. Test representative examples and confirm tensor shapes and allowed ID ranges. During upgrades, verify that tokenization and decoding remain compatible. Refuse mismatched configurations rather than silently accepting ID sequences that point to incorrect embedding rows.
