1. What is a positional embedding, and why does a Transformer use positional information?

Correct: C. A token embedding encodes features associated with a token, while positional information indicates its place in the sequence. Standard self-attention does not by itself provide the model with a complete sense of word order. Positional embeddings or other positional methods make different arrangements of the same tokens easier to distinguish.

2. Why does token order matter in sentences such as 'dog bites man' and 'man bites dog'?

Correct: A. These sentences contain the same vocabulary items but describe different events. Order tells us which entity does the action and which receives it. If a model only considered an unordered set of token identities, it could lose this distinction. Positional signals help preserve relationships that depend on sequence order.

3. How are learned absolute positional embeddings commonly added to token embeddings?

Correct: D. In a common absolute-position design, the model learns a vector for each supported position. That vector usually has the same width as the token embedding and is added at the corresponding index. This supplies both identity and location information before the Transformer blocks. Some models instead use rotary or relative position methods.

4. How do learned positional embeddings differ from fixed sinusoidal positional encodings?

Correct: B. Learned positional embeddings are parameter values updated during model training. Sinusoidal encodings instead use predetermined sine and cosine functions of position and dimension. Both supply information about order, but they differ in how they are constructed and how they may handle lengths beyond those used in training. Architecture determines the method.

5. What changes when the same token appears at two different positions in an absolute-position model?

Correct: C. The same token can retain its token ID and starting token embedding at different locations. Its positional vector differs according to the sequence index. Combining the two produces different model inputs for each occurrence. Later attention and feedforward layers add context-dependent effects, so final representations can differ further.

6. Why might a model with learned absolute positional embeddings reject an extremely long input?

Correct: A. A learned absolute-position table usually supports a configured set of indices. Positions beyond that range may not have trained vectors available. Longer-context support requires a deliberate design or extension and testing. Other positional methods can differ, but memory, attention cost, and reliable use of long information still impose practical limits.

7. A text classifier works on short inputs but struggles on long documents. What should you inspect?

Correct: D. Long inputs may be truncated, may exceed supported positions, or may contain information the model fails to use reliably. Inspect token counts and whether critical passages survive preprocessing. Check the configured positional mechanism and evaluate on realistic long examples. Do not assume that theoretical context capacity guarantees dependable document understanding.

8. In an interview, how would you choose a positional approach for long-document Transformer models?

Correct: B. Define the required document lengths and performance budget first. Compare positional methods supported by the architecture, testing accuracy, runtime, and memory on representative long examples. Examine behavior beyond training lengths and avoid unnecessary changes to a pretrained model's positional scheme. The best option depends on measured workload rather than theoretical claims.
